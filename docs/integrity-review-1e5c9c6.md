# ImprintSites integrity review · 21 November 2026

**Keep paid launch on hold.** Four ordinary merchant and shopper workflows produced incorrect orders, stock, or catalog data on the release Worker. The earlier fixes for decimal commas, SKU-scoped prices, ambiguous variants and replaying an individual product edit passed their regressions. The next merchant fixes belong in the Worker that accepts orders today. The Python read pilot can continue independently.

## Findings in customer-impact order

The eight findings below were reproduced on isolated D1 through the built Worker or in Chrome. P1 means a wrong order, stock quantity, or loss of merchant data. P2 covers recoverable data loss or a misleading or inaccessible workflow. The tests in the last column are acceptance criteria for the repair.

| Priority | Reproduction and customer impact | Acceptance test |
|---|---|---|
| P1 | **Checkout records a higher total than the shopper saw.** Two scarves quoted at €20 total. The seller doubled the unit price while checkout was open. Submitting the same cart created a €40 pay-on-delivery order. The browser submits quantities and method IDs. The Worker recomputes prices but lacks the quote the customer accepted. [Checkout form](../src/shared/render/runtime.ts#L42) · [Order creation](../src/worker/routes/public.ts#L160) | Change a price or delivery fee after quoting. The first submit must return a revised quote and create zero orders or stock movements. Only explicit acceptance can place the order at the new total. |
| P1 | **An older product form deletes another editor’s variant.** Open the same one-color scarf twice. The first editor adds Green with 7 units. The second only renames the item. Both saves return 200 and Green disappears. Every variant absent from the old form is treated as a deletion. [Product save](../src/worker/routes/commerce.ts#L209) | Replay those two edits from distinct forms. Preserve Green’s ID and stock or return a conflict before any change. Also test an intentional deletion from a current form. |
| P1 | **Retrying a stock CSV restores units already sold.** Import stock 8, sell 2, resend the identical import. Stock goes from 6 back to 8. Each delivery creates a fresh stock-edit ID. This is distinct from the corrected product-editor retry. [CSV update](../src/worker/routes/commerce.ts#L360) | A repeated delivery of the same import must keep 6 and create no additional movement. A merchant starting a new stock count against the updated catalog must still be able to set 8. |
| P1 | **Cancellation can add units that checkout never deducted.** Sell 2 from a variant with inventory tracking off and stock 5. Enable tracking with stock still 5, then cancel. Stock becomes 7. Checkout and cancellation each use the tracking setting at the time of their own operation. [Checkout debit](../src/worker/routes/public.ts#L182) · [Restocking](../src/worker/routes/commerce.ts#L470) | Record the actual inventory debit on the order and reverse it exactly once. Cover both directions of the tracking change and a repeated cancellation. |
| P2 | **A previous client’s inspiration URL carries into a new project.** In the same tab, start a business project with a reference URL, then create a personal project directly from the dashboard. The personal project’s saved intake contains the first project’s URL. Its Style step can auto-analyse that reference. [Intent creation](../src/client/pages/Home.tsx#L80) · [Project creation](../src/client/app/App.tsx#L112) · [Style step](../src/client/app/Wizard.tsx#L108) | Keep the intended brief through sign-up and refresh, consume it on successful creation, and verify a second project or a different signed-in account starts empty. Remounting the Style step should not start a second request for the same analysis. |
| P2 | **The wizard loses an edit on immediate reload.** Type a professional title, refresh before the 900 ms debounce, and the field reopens empty. The save state only changes when the request begins. Step navigation also suppresses a failed save after advancing. [Autosave](../src/client/app/Wizard.tsx#L43) · [Step navigation](../src/client/app/Wizard.tsx#L56) | Reload during the debounce and recover the edit or give the user a chance to stay. Delay one save and fail another. Preserve the newest answers and make any unsaved state visible. |
| P2 | **An invalid chosen address is silently replaced.** Enter `ab` as the address, see the three-character minimum, then press Continue. A project is created at the name-derived address. [Create payload](../src/client/app/App.tsx#L114) · [Continue button](../src/client/app/App.tsx#L147) | A manually entered invalid or unchecked address must block creation with a field error. Delay two availability responses and ensure only the latest applies. |
| P2 | **Keyboard focus leaves a destructive dialog.** In the editor’s Delete section dialog, Tab moved focus into the page while the dialog remained open. Escape closed it. Separately, opening the homepage URL field produced two elements with ID `insp`, including the heading naming the inspiration region. Both observed in Chrome. [Dialog keys](../src/client/lib.tsx#L172) · [Homepage field](../src/client/pages/Home.tsx#L116) · [Region](../src/client/pages/Home.tsx#L185) | Tab and Shift+Tab stay inside, Escape restores focus to the trigger and Enter resolves once. In the expanded homepage state, every label and region must resolve to exactly one intended element. |

## Maintainability and missing tests

The line counts point to places where a change can affect several customer workflows at once. A wholesale rewrite would do little for the four P1 failures. These extractions each protect a specific invariant.

|---|---|
| `commerce.ts` has 497 lines. Request decoding, catalog replacement, stock deltas, import matching and order transitions share a module. | First extract a pure variant-change planner that takes the base catalog and an explicit add/edit/remove set. Keep D1 writes in one transaction. Test a stale form, intentional deletion and replay. Then isolate the stock ledger shared by order placement and cancellation. |
| `projects.ts` has 533 lines. Multiple endpoints decide revision numbers, save the document, rebuild indexes and record history. | Give draft persistence one compare-and-set operation with the expected revision. Have autosave, AI changes, checkpoint restore and template changes call it. Add the two-writer test before moving another endpoint to Python. |
