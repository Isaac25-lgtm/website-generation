## Findings to return to engineering

1. **P1 · Admin Settings cannot save after the registry initializes.** In local Chrome, a signed-in admin opened Settings and clicked Save without editing anything. The Worker returned HTTP 400 with `Unknown setting template_registry`. The form includes every returned setting except keys starting with `demo_seed`, sends the entire object, and only renders inputs for its hard-coded labels. The registry sync adds an internal key that the write API correctly rejects. The API accepts the budget key, but the form displayed **zero** assistant budget inputs. See `src/client/app/Admin.tsx:131–140`, `src/worker/routes/admin.ts:144–160` and `src/worker/seed.ts:28–31`. **Acceptance:** on an initialized database, save an ordinary setting and set the assistant budget to zero through the UI. Verify both persist, chat pauses, and internal keys stay read-only.
2. **P1 · Assistant spend accounting does not support a hard daily dollar ceiling (#5).** The conditional reservation is atomic, but the request uses a character-based estimate and settles actual usage afterward. Requests can cost more than reserved. A locally aborted or unreadable upstream response releases the reservation as zero even when provider billing is unknown. Both reservation and settlement independently compute today's date. In a clock-controlled test, a request reserved 1,500 tokens just before midnight UTC and completed just after midnight with 780 used. The previous day's row retained all 1,500 reserved and recorded **zero used**. See `src/worker/routes/assistant.ts:71–84,107–112,135–147`. The endpoint also buffers the entire body before enforcing its character limit when no usable length header is present (`assistant.ts:92–95`). **Acceptance:** tie settlement to the reservation's day and ID, reserve a conservative provider-aware bound, retain an allowance for uncertain bills, and enforce the byte limit while reading. Exercise overlapping calls, midnight, timeout and usage above estimate. A model-dependent token allowance and a guaranteed billing limit need different evidence. [DeepSeek pricing](https://api-docs.deepseek.com/quick_start/pricing/)
3. **P2 · Unsent chat text survives logout (#10).** In Chrome, I entered an unsent note, closed the chat, signed out and reopened the widget on the signed-out homepage. The note was still in the input. Sent history is scoped per account and late replies are discarded, but draft text, busy and status are separate state. An old request also unconditionally clears busy in its finally block. See `src/client/components/Assistant.tsx:25–45,61–75`. **Acceptance:** reset all conversation state on identity change and ignore stale finalizers. Cover a typed unsent draft, a pending request, and Clear followed immediately by another send.
4. **P2 · Hosting answers still overstate the billing state (#8).** The assistant now shares configuration values and lists all five offline payment options. But it calls `not_set` “announced” and says every published site is charged whenever an admin selects `active`. That setting does not collect recurring payments. The UI explicitly says fees are never charged automatically. The assistant and browser also choose different defaults when individual hosting amounts are missing. See `src/worker/routes/assistant.ts:37–43`, `src/client/lib.tsx:120–134`, `src/client/app/Admin.tsx:138` and `tests/unit/assistant.test.ts:149–150`, which currently asserts the unsupported claim. **Acceptance:** test all three states against actual collection capability and the customer's pricing display, including missing amounts.
5. **P2 · Member HTML remains fresh in the browser cache after access changes (#1).** The origin now gates full member pages and allows a reduced home thumbnail. Signed-in full HTML still carries `private, max-age=600`; logout does not invalidate that cache, and the response does not vary on the session cookie. A shared browser can reuse its own cached member response during that window. This is a source-level cache-policy finding, distinct from the old anonymous origin route. See `src/worker/routes/sites.ts:118–134` and `src/worker/routes/auth.ts:58`. **Acceptance:** use `no-store` for full member HTML and verify a same-browser sign-out/revisit. The thumbnail is static HTML rendered with the normal header/footer, not an image file.
6. **P2 · Owner photos are protected in public rendering, but historical private reads still expose references (#2).** Renderer modes, catalog writes, rendered legacy catalog rows, exported site.json and the Python draft reader have protection. The Worker project read still returns a parsed historical draft without cleanup. Copied intake and Python intake responses still carry the original JSON, and the product-management read parses the stored images directly. See `src/worker/lib/site.ts:31–35`, `src/worker/routes/projects.ts:118–119,168`, `src/worker/routes/commerce.ts:99` and `backend/imprint/views.py:198–200`. This is a private-data consistency issue; no public rendering leak was demonstrated in the fixed paths. **Acceptance:** pass legacy records through both project readers, duplication and the product-management response, alongside the existing HTML/export tests.
7. **P2 · Deleted stock paths can break existing customer images.** The two branded files are gone, and their new references point to replacement photos. Local requests for both old image URLs returned **200 text/html** from the SPA fallback. The replacement returned **200 image/webp**. The renderer still forms asset URLs directly from stored names at `src/shared/render/sections.ts:56–79`. Production use of those names was not queried. **Acceptance:** keep brand-free replacement images at the old paths or supply compatible mappings for stored and previously exported references. Assert an image MIME type and a decodable image at both old URLs.
