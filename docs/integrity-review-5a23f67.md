# ImprintSites integrity review · 25 November 2026

**Decision: pause bulk template additions and keep the help assistant off.** The current Worker has room for the library. The immediate problems are who can retrieve a full preview, which images and claims reach a merchant's published site, and what the assistant sends to its provider. The architecture can support more designs once these rules are enforced and tested centrally. The existing paid-launch hold also remains in force.

Reviewed [release 5a23f67](https://github.com/Isaac25-lgtm/website-generation/commit/5a23f67) against the handoff on [main at 5c6ce26](https://github.com/Isaac25-lgtm/website-generation/commit/5c6ce26). File and line references below refer to the release. All customer accounts, grants, builds and orders used for this audit were local. Source findings and observed failures are distinguished below. No application changes, commits or deployments were made.

No P0 finding was established in this review. P1 items affect access, customer trust, or safe activation of a feature. P2 items affect customer experience, reliability or a stated content rule. P3 items are maintenance and performance work.

## Code integrity and test coverage

- **Registry and render contracts.** The registry contains 63 business, 93 personal and 143 store templates. The registry test checks unique IDs and matching personas. All 299 committed valid fixtures were present; the JSON Schema snapshot and TypeScript validation passed. The fixture test at `tests/unit/contracts.test.ts:38` can create a missing file before later validation. Run fixture inventory as a read-only CI assertion and keep regeneration explicit. Python parity was outside this run.
- **Variant names.** At `src/shared/templates.ts:39–44`, hero names are arbitrary strings and layouts are a union across site types. A typo can silently select the default renderer at `src/shared/render/sections.ts:272`; checking for a visible heading does not catch the substitution. Use a typed hero-key registry for authored templates, keep a compatible fallback for stored documents, and assert the expected rendered hero class for every template.
- **Small refactors.** Extract the near-identical row mapper at `src/shared/templates-store2.ts:59` and `src/shared/templates-store3.ts:101`, preserving batch 3's extra standard rank. Share the persona row mapper at `src/shared/demo-store2.ts:195` and `src/shared/demo-store3.ts:323` as part of finding 14. Centralize the product-card class lookup at `src/shared/render/store.ts:50,120` so listing and related products agree. Keep the three hero families readable as separate modules. A rewrite of all renderers would add risk without fixing these defects.
- **Styles and inventory.** The authored hero CSS scan inspected 944 selectors, including keyframe steps. The unscoped exceptions were keyframe steps and the dedicated fame/awards sections. Global base styles can still affect a class *inside* a hero, as Bookcover demonstrates. Layout sheets intentionally affect header, cards and footer across their own page. The obsolete `.show-tabs`, `.show-grid`, `.show-tile`, `.show-foot` and `.btn-light` rules at `src/client/styles.css:204–216` have no non-CSS source consumers. Remove that block after a gallery comparison. Preserve shared thumbnail and bento styles.
- **Test strength.** The all-template unit render exercises routes and missing pages. The Chrome loop visits every registered member preview but asks only for the first visible h1; its list threshold is 43 and the check can pass on an access-gate page. It took 3.8 minutes. Assert catalog-to-fixture ID equality, exact template/hero identity, HTTP status, one main heading and link targets in the fast render suite. Keep authenticated browser checks for route access, all distinct layouts and interactive paths. Save screenshots on failure or intentional visual review. The assistant E2E accepts the feature-off message and cannot certify provider success.
- **History and attribution.** No reachable commit touched the named plaintext file `tests/unit/source-tokens.json`. I scanned 729 eligible unique text blobs reachable from local Git refs, plus commit messages, using the supplied hash/token rule. There were token hits in 59 historical paths and 35 current source/public/docs paths; commit-message hits were zero. A word hash match does not identify a complete domain or an individual. The hashes also cannot prove absence in binary media, unreachable commits, renamed non-text files or external forks. ### Runtime and assistant cost

Wrangler measured the complete Worker bundle at **1,867.87 KiB uncompressed and 445.43 KiB gzip**. The local startup profile was **158.1 ms active**, including 2.1 ms GC, in a 309.8 ms window. The published limits checked for this review are 64 MiB of Worker code and one second of startup. The largest generated template home by HTML size was `e-craft` at 78,285 bytes; the smallest was 57,657 bytes. Across 100 warm repetitions of generation, catalog assembly and rendering for `e-craft`, Node recorded **1.57 ms median, 2.70 ms p95 wall time and 2.03 ms mean process CPU**. The measurements exclude D1, network and browser layout; production request CPU and cold latency need deployed telemetry. The practical scaling concern today is repeated HTML/CSS in gallery cards and eager browser transfer. [Cloudflare Workers limits](https://developers.cloudflare.com/workers/platform/limits/)

For a concrete assistant budget example, 10,000 calls averaging 6,000 uncached input tokens **including the system prompt** and 500 output tokens would cost about **$12 off-peak or $24 peak** on the documented Flash rates ($0.15/$0.30 for a million input tokens, $0.60/$1.20 for a million output tokens). This is a scenario, not a daily ceiling or measured traffic. Token counts depend on language, history, model and cache; 24,000 characters is not a token limit. The code accepts a model override, which can change the cost. [DeepSeek pricing](https://api-docs.deepseek.com/quick_start/pricing/)

## Suggested order for the next engineering pass

The local preview was stopped after verification. Automatic command review blocked recursive cleanup of the disposable `template-review-1795592586837` checkout beside the repository. It contains local test artifacts and a junction to the repository's installed dependencies. The only change inside the Git working tree is this report.

1. **Protect what is public.** Separate gallery thumbnails from full previews and enforce owner-photo policy on catalog, rendering and export. Add the acceptance tests for findings 1 and 2 before changing routes.
2. **Make templates truthful and usable.** Remove unrequested merchant claims, resolve links from the actual document, fix narrow product grids and replace branded images. Test with both populated stores and sparse customer intake.
3. **Keep chat disabled until its activation criteria pass.** Use a supported model and shared product facts, correct the privacy notice, contain spend and isolate conversations. Run provider-stub tests in CI. A real staging check can follow when the owner chooses to enable the feature.
4. **Then resume adding designs.** Compose the kit registry explicitly, share row/card mappings and enforce template-to-renderer coverage. Measure the browser bundle and replace gallery HTML thumbnails as part of the access-control fix. The existing TypeScript renderer can remain in place for these changes; a backend migration is independent of them.
